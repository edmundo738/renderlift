# D3D9 backend — integration plan

**Priority: second wave.** Target libraries: Source engine (CS:S, HL2, Portal,
L4D2), GTA IV, Skyrim (2011), Fallout 3/NV — the classic low-end catalog.

## Presentation model

No DXGI: the device itself presents — `IDirect3DDevice9::Present` — and
`IDirect3DDevice9::Reset` re-creates the backbuffer in place (windowed ↔
fullscreen switches included). Both must keep our redirection state coherent.

## Planned hook targets (module contract)

- `IDirect3DDevice9::Present`
- `IDirect3DDevice9::Reset`
- `IDirect3DDevice9::CreateRenderTarget`
- `IDirect3DDevice9::SetRenderTarget`
- `IDirect3DDevice9::SetViewport`

## Notes vs D3D11

- Interception is simpler (device vtable only); compute shaders do **not**
  exist → ALRR reconstruction runs as pixel-shader passes (SM 3.0 minimum;
  SM 2.0 fallback considered per title).
- Many D3D9 games expose their own resolution setting to everything — the
  steering trick can lean on that (`SetViewport` + RT swap) instead of deep
  texture patching.
- `Reset` semantics mean "device lost" handling matters: our internal
  resources must recreate alongside the game's, or the first Alt-Tab crashes.
