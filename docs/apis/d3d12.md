# D3D12 backend — integration plan

**Priority: later, explicit.** D3D12 is deliberately *not* treated as
"D3D11 with different names".

## Why it's structurally different

| D3D11 world | D3D12 reality |
|---|---|
| runtime validates state, we patch vtables | the game owns command lists; work is recorded then submitted via `ExecuteCommandLists` |
| RTVs bound per draw implicitly | descriptors in heaps; RTV creation tracked via `CreateRenderTargetView` on heaps |
| driver tracks resource states | **the app owns states**: our compute pass needs `COMMON→UNORDERED_ACCESS→PRESENT_SOURCE`-style `ResourceBarrier`s inserted in the right command list |
| swap chain present is one call | `IDXGISwapChain3::Present` still exists, but the backbuffer's state transitions are visible | 

## Planned hook targets (module contract)

- `ID3D12CommandQueue::ExecuteCommandLists` — where our reconstruction
  dispatch gets appended (own tiny queue first; in-place later)
- `IDXGISwapChain3::Present` / `IDXGISwapChain::ResizeBuffers`
- `ID3D12Device::CreateRenderTargetView` — backbuffer/scene RT registry
- `ID3D12GraphicsCommandList::RSSetViewports`, `::OMSetRenderTargets` — steering
- `ID3D12GraphicsCommandList::ResourceBarrier` — state tracking of scene targets

## Consequences for the design

- **In-place injection is brittle** (closed command lists, bundles). Phase 1:
  post-queue wrap — run ALRR on our own queue between game submission and
  present. Phase 2: bundle splice per profile.
- Backend needs its own allocator + descriptor heaps sized for ALRR passes.
- The payoff on UHD-class iGPUs is questionable anyway: this module exists
  for *catalog coverage* (modern titles), not for the first lab.
