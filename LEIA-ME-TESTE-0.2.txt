★ O QUE MUDOU NESTA v3 (resposta ao crash 0xc0000005 do teste anterior)
  A instalação no processo remoto foi reescrita para ser "evidence-first":
  • RenderLiftInstall/Uninstall/FrameCount têm agora a forma EXATA de uma
    thread do Windows (HRESULT WINAPI fn(LPVOID)) — a chamada remota do
    Loader é ABI-perfeita, não apenas compatível;
  • o módulo escreve checkpoints no log a partir da PRIMEIRA instrução,
    sem depender de STL/globals/locks ("RLCAP1 install cp=1,2,3,…");
  • o log sai AO LADO DA DLL por omissão (C:\RenderLift-lab\) — nunca na
    pasta do jogo; se nem aí der, cai para %TEMP%;
  • qualquer exceção é registada com fase + código + endereço exato
    ("RLCAP1 seh phase=… code=0x… addr=0x…") e devolvida como código;
  • falhas normais devolvem códigos distintos por passo (ver tabela abaixo).

──────────────────────── PASSO 0 — MARK OF THE WEB (arquivos baixados) ───
  Ficheiros baixados da internet recebem a marca de segurança do Windows
  ("Zone.Identifier"). Sem desbloquear podes ver:
    • SmartScreen: "O Windows protegeu o seu PC" ao correr o Loader;
    • bloqueios silenciosos carregando a DLL no GTA V;
    • erros de acesso ao escrever o ficheiro de log.
  Solução (qualquer uma):
    A) Clica-direito no .zip → Propriedades → marca "Desbloquear" → OK,
       e só depois extrai (extrai com "Extrair tudo", NÃO corre EXEs
       de dentro da janela do zip);
    B) Depois de extrair, em PowerShell:
       Get-ChildItem "C:\RenderLift-lab" -Recurse | Unblock-File
    C) Se SmartScreen ainda aparecer no Loader: "Mais informações" →
       "Executar assim mesmo" (o binário não é assinado — é build de CI;
       o código fonte completo está no repo para conferência).

═══════════════════ SE FALHAR: COMO LER A EVIDÊNCIA (novo na v3) ─
  O log conta a história completa da instalação, checkpoint a checkpoint:
    RLCAP1 install cp=1   entrou no RenderLiftInstall
    RLCAP1 install cp=2   bloco de estado construído
    RLCAP1 install cp=3   log aberto
    RLCAP1 install cp=4   motor de hooks (MinHook) inicializado
    RLCAP1 install cp=5   a resolver vtables (probe D3D11)
      cp=50..55  sub-passos: register-class, create-window, probe HW/WARP,
                 leitura das vtables, cleanup
    RLCAP1 install cp=60..68  cada um dos 9 hooks instalado
    RLCAP1 install cp=70  enableAll
    RLCAP1 install cp=80  ARMED — a partir daqui é só observação

  → O ÚLTIMO cp visível diz exatamente onde parou. Manda-me o log mesmo
    (sobretudo!) se o jogo crashar: a última linha é o diagnóstico.
    Se não aparecer NENHUM cp=1: o problema está antes da nossa DLL
    (loader/AV/permissões) — também me diz.

  Código devolvido pelo Loader ("remote RenderLiftInstall returned 0x…"):
    0x00000000   sucesso, módulo armado
    0x8000A001   falha a alocar estado        0x8000A010  vtables falharam
    0x8000A002   log não abriu                0x8000A02i  hook i falhou
    0x8000A003   MinHook init falhou          0x8000A030  enable falhou
    0xE?xxxxxx   exceção: ? = fase, xxxxxx = código Windows
                 (ex.: 0xE5C00005 = acesso inválido na fase 5, vtables)

═══════════════════════════════════════════════ PROBLEMAS TÍPICOS ─
  "OpenProcess failed (5)" — terminal como Administrador; fecha overlays
    hook-ativos (RTSS/Discord/NVIDIA overlay) se falhar.
  "export 'RenderLiftInstall' not found" — estás com o build ANTERIOR:
    apaga tudo e baixa o pacote novo (lembra do Unblock-File).
  Sem "module armed" — confirma que a DLL está na mesma pasta que o Loader.
  Log é só "hello" sem "present" — manda tal como está; já é informação.
  Crash no jogo? Manda o log parcial: a última linha "cp=N" (ou a linha
    "RLCAP1 seh …") identifica o ponto exato da falha.
